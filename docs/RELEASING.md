# 构建与发布

`0.6.0-preview.2` 将安装向导初始化阶段与目标目录读取分开：初始查找只访问显式参数和客户端注册项，客户端页面显示后通过 `WizardDirValue` 读取当前默认位置。最终安装准备和卸载阶段才使用 `app` 常量。正常交互启动回归必须不传 `/NCMCLIENT`、`/DIR` 或静默参数，避免显式参数掩盖默认路径中的错误。

当前扩展版本为 `0.6.0-preview.2`，采用客户端本地自动加载及内部结构、接口检测。安装后直接打开原网易云程序和快捷方式。真实客户端播放实测基线仍为 `3.1.42.205594 x64`；不能把自动识别能力写成“所有网易云版本均已支持”。此项目尚无自动更新器；用户手动下载发行包并安装。没有签名证书时，构建产物应明确标为未签名，不能把 SHA-256 校验称为 Authenticode 签名。

## 本地构建

要求 Windows x64，使用系统自带 Windows PowerShell 5.1 或 PowerShell 7，以及 Windows 上可用的 .NET Framework C# 编译环境。先检出源码，再执行：

```powershell
powershell.exe -NoProfile -File .\scripts\build.ps1 -Version 0.6.0-preview.2
```

`-Version` 使用不带 `v` 的版本号。发布标签使用同一版本并增加 `v` 前缀，例如 `v0.6.0-preview.2`。产品版本与 Windows 的四段文件版本由构建脚本统一处理，不手动修改构建出的二进制版本资源。

固定组件的来源、版本和校验值由 `dependencies.lock.json` 管理。Python 运行环境和其他组件在构建时取得；缺少 Inno 编译器时，脚本会在项目 `.build/` 下缓存固定的 Inno Setup 6.7.4 工具。可用 `-InnoCompiler` 指定已有的 `ISCC.exe`。清理 `.build/` 会导致下次重新下载，不应把该缓存提交到仓库。

本版还构建 x64 原生自动加载器。构建脚本从锁定来源准备 Zig 工具；可用 `-ZigCompiler` 指定已有编译器。自动加载器源码和导出转发定义保留在 `src/autoload/`，不从用户的网易云目录复制库文件作为发布产物。

变更 Python、Frida、websocket-client、兼容检测规则或打包工具后，重新运行测试和真实客户端回归。不要把“固定了版本”表述为已经完成逐位可复现构建。

`dist/` 应包含安装程序、运行文件 ZIP、源码 ZIP 和覆盖这三个文件的 `SHA256SUMS.txt`。运行文件 ZIP 是手动运行、调试或部署工具用途，解压本身不会安装自动加载。面向普通用户应推荐安装包。发行包应带使用文档、项目许可及完整的第三方许可。不要把缓存下载、个人日志、用户音乐、本机绝对路径、设备 ID 或临时验证记录打入仓库和发行包。

## GitHub Actions

仓库带有 `.github/workflows/build-release.yml`：

- Pull request 和主分支提交：检查并构建，只上传 Actions 构建产物，不创建 Release。
- 手动 `workflow_dispatch`：默认只构建。填写不带 `v` 的版本号。
- 推送 `v*` 标签：构建并发布对应 GitHub Release。含预发布后缀的版本标为 prerelease。
- 在已有标签上手动运行时，只有显式选择 `publish` 才进入发布任务。分支上的手动构建不会发布。

标签发布需要该仓库允许 Actions 创建 Release；工作流仅给发布任务 `contents: write`，普通构建保持只读。不要使用 `pull_request_target` 来构建外部贡献代码。

准备好仓库和发布内容后，由仓库维护者执行：

```powershell
git tag v0.6.0-preview.2
git push origin v0.6.0-preview.2
```

推送标签会实际触发发布。工作流不能代替维护者确认兼容性、发行说明、组件许可与签名状态。已公开的 Release 不应使用相同标签替换成另一套构建；修复后增加版本号。

## 自动兼容规则的发布验证

启用依据是当前文件和进程中的结构检查，不是网易云产品版本号或历史文件哈希是否位于白名单。新增客户端的哈希可以记录为诊断与实测证据；仅添加哈希不能证明新结构兼容。

发布前检查 PE 签名唯一性、`.pdata` 函数边界及 `CreateThread` 导入关系；核对 FFmpeg 导出、加载模块归属与运行时 ABI **58 / 56 / 3**；检查实际加载的 webpack 模块及输出设备、音量接口调用约定。缺失、重复、位置改变、重定位或接口异常应有独立测试，且失败后应保持或恢复普通网易云输出。

本地自动加载还必须检查客户端 CEF 初始化入口、相关导入与转发契约。启动 helper 的等待发生在加载器锁以外；只读原生预检通过后，才允许进入可能修改音频流的阶段。原始命令行已有手动管理或旁路标记时不重复接入，避免两个控制器叠加。

发布说明应分别列出真实播放验证过的客户端和仅经模拟验证的结构变化。目前真实实测只有 `3.1.42.205594 x64`；函数重定位、相对地址与随机模块编号等模拟验证不能写成已经完成多个真实客户端版本的播放回归。遇到新的 FFmpeg ABI 或不同音频架构，先扩展规则并完成回归，不通过降低检查要求来宣称“版本无感知”。

## 签名和校验顺序

如维护者持有可用的代码签名证书，使用受保护的发布环境执行 Authenticode 签名并验证证书身份。不要把 PFX、密码或私钥提交到仓库。

正确顺序为：构建 → 签名需要签名的可执行文件 → 重新生成最终便携包 / 安装包 → 对最终文件生成 SHA-256 → 上传同一组产物。安装程序自身的签名也会改变文件内容，因此校验清单必须在所有签名步骤结束后生成。

本工作流没有预置签名密钥，也不会自动声称产物已经签名。若增加签名步骤，应让未配置密钥的构建保持明确的未签名状态，并在 Release 说明中标注。

## 第三方许可及对应源码

发布前逐项检查 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 与实际安装包里的组件一致：

1. 保留 Python 分发中的 `LICENSE.txt`，包括其中的第三方声明。
2. 保留 Frida wheel 的 `COPYING`、其引用的 `COPYING.LIB` 及分发附带的其他许可，不把 Frida 统一改标为 MIT。
3. 保留 websocket-client 的 Apache-2.0 `LICENSE` 及上游分发中存在的 NOTICE / 版权声明。
4. 记录运行组件准确版本、取得的归档文件和 SHA-256；如果修改上游组件，记录补丁与来源提交。
5. 保留准确版本的源码来源。当前使用未修改的上游 Frida wheel，并保留其 wxWindows 许可例外；不要额外填写未经安排的书面源码承诺。若以后修改上游组件或改变其分发方式，重新核对相应条款并准备需要的源码、构建资料与修改记录。

Frida 的官方源码入口与版本已在第三方声明中列出。获取完整检出可使用：

```powershell
git clone --branch 17.25.1 --recurse-submodules https://github.com/frida/frida.git frida-17.25.1-source
git -C frida-17.25.1-source submodule update --init --recursive
```

GitHub 自动生成的 “Source code.zip” 通常不包含 Git 子模块内容，不能仅凭文件名将它描述成所有打包原生依赖的完整对应源码。维护者需要对实际使用的二进制来源做匹配；保留源码来源说明不等于已经检查全部原生依赖。

## 升级和卸载回归

默认采用需要管理员权限的机器安装，运行文件放在 `%ProgramFiles%\NcmWasapiExtension`。这使附加到客户端的本地加载组件指向受保护的程序文件，而不是某个普通用户可写的运行目录。用户配置和日志仍按用户保存在 `%LOCALAPPDATA%\NcmWasapiExtension`。

首次安装要求选择或确认网易云 `cloudmusic.exe`，并完全退出该客户端。安装器在所选网易云目录增加本项目的 `msimg32.dll`、`ncm-wasapi-autoload.ini` 和 `.ncm-wasapi-autoload.json` 归属记录；不替换 `cloudmusic.exe`、`cloudmusic.dll` 或其他原客户端文件。未知、已有 BetterNCM 或内容已改变的 `msimg32.dll` 不能覆盖。

分别验证首次安装、原图标 / 原 exe 自然启动、覆盖升级、用户正常退出、运行中安全关闭、卸载和普通启动恢复。原有手动启动测试不能替代自然启动验证。没有开机常驻 watcher、全局启动拦截或安全功能关闭步骤。

安装目录必须为空，或包含本项目匹配的 `.ncm-wasapi-install` 标记和必要程序文件。未知非空目录以及含网易云客户端文件的目录不能用作安装目标。不要把该标记复制到其他应用目录来绕过检查。

安全关闭成功后，覆盖升级会重建扩展自己的 `runtime` 并清理程序根目录的 `__pycache__`，避免旧版本已移除的模块或运行缓存残留。卸载按同一目录归属检查清理这些程序文件。用户配置和日志位于安装目录之外的 `%LOCALAPPDATA%\NcmWasapiExtension`，升级和卸载保留该目录。

卸载应先等待网易云完全退出，再根据本项目的归属记录及内容校验移除自动加载文件；发现其他来源或被改变的文件时停止并报告，不能将其接管为本项目文件删除。卸载只移除扩展自己的文件、快捷方式及注册项，不删除网易云账户、缓存或下载目录。如果未来加入自动更新，应独立设计版本来源、签名验证、失败恢复与用户控制；当前项目不启用这些机制。
